### `search_listings`

- **What it does:** Searches thrift clothing listings and filters items based on the user's description, preferred size, and maximum price.
- **Inputs:** `description` (str), `size` (str), and `max_price` (float).
- **Returns:** A list of matching clothing records. Each record contains an item ID, title, description, category, style tags, size, condition, price, colors, brand, and selling platform.
- **When it has nothing:** Returns an empty list (`[]`). The agent stops the outfit recommendation process and asks the user to adjust their search criteria.

### `suggest_outfit`

- **What it does:** Generates outfit recommendations by combining a selected thrift listing with compatible clothing items from the user's existing wardrobe.
- **Inputs:** `new_item` (dict), containing the selected clothing listing, and `wardrobe` (list of dicts), containing the user's existing clothing items.
- **Returns:** An outfit recommendation containing the selected thrift item, suggested wardrobe pieces, and a brief explanation of how the pieces work together.
- **When it has nothing:** If the wardrobe is empty, provides general styling suggestions for the selected item without referencing clothing the user does not own.

### `create_fit_card`

- **What it does:** Generates a short, engaging fashion caption that describes the recommended outfit and highlights the selected thrift item.
- **Inputs:** `outfit` (dict), containing the outfit recommendation, and `new_item` (dict), containing the selected thrift listing.
- **Returns:** A fit card containing a fashion caption that identifies the selected item and describes the overall outfit style.
- **When it has nothing:** If the outfit information is missing or invalid, returns a clear error message instead of generating an inaccurate caption.

## Planning Loop

**Branch rule:**

If `search_listings()` returns an empty list, the agent saves an actionable error message in `session["error"]` and stops. Otherwise, it selects the first search result, generates outfit recommendations using `suggest_outfit()`, and creates a fit card using `create_fit_card()`.

**Where it lives:** `agent.py::run_agent`

**How the query is parsed:**

The agent uses Python regular expressions (`re`) to extract the maximum price and clothing size from the user's query. It then removes these constraints from the original query to obtain the clothing description. The extracted values are passed to `search_listings()`.

**What moves through the session:**

The agent stores information in the session dictionary in this order:

1. `query` — the user's original clothing request.
2. `wardrobe` — the user's existing clothing items.
3. `parsed` — the extracted description, size, and maximum price.
4. `search_results` — clothing listings returned by `search_listings()`.
5. `selected_item` — the first matching product.
6. `outfit_suggestion` — personalized outfits generated by `suggest_outfit()`.
7. `fit_card` — the final fashion caption generated by `create_fit_card()`.

If no matching products are found, the agent stores a message in `error` and returns the session without generating an outfit or fit card.

I updated the keyword-matching logic in `tools.py::search_listings()`. Previously, an item could appear in search results if it matched only one word from a multiword query. All 15 scenario runs completed as expected after the improvement. The change reduced loosely related results without disrupting the tested agent workflows. Some imperfect matches remain, so search relevance still has room for improvement.
